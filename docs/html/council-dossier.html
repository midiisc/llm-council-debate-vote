llm-council-debate-vote — multi-agent debate pipeline

Council Dossier

Four models draft an answer independently, review each other under exclusion rules that block a model from voting on its own work, revise only when they actually disagree, and one designated chairman signs the synthesis — with a fifth voice standing by to attack that synthesis before a human ever reads it. This is the record of how each stage is built, why it exists, and — honestly, not optimistically — which parts are live today versus still on paper.

Rationale

Why not just ask one model

A single frontier model answers with its own blind spots uncorrected — confident and wrong looks identical to confident and right from the inside. The premise of this pipeline is that independent drafts, forced cross-critique, and evidence-gated revision converge on something a lone pass can't self-check. That premise only holds if the mechanics enforcing it are real rather than cosmetic — which is what every stage below is built, and audited, to guarantee.

The pipeline doesn't treat multi-agent debate as an unconditional upgrade. One of the literature findings this project keeps on file, deliberately, is a caution against overselling it: on an open-ended, human-expert-judged writing task, domain experts preferred a single frontier-model pass over a multi-agent debate variant that burned roughly 30× the tokens for a worse-liked result. That's why Stage 0 — a human writing down decision criteria and kill-switches before seeing any model output — stays manual by design, and why revision at Stage 2.75 is gated on actual measured disagreement rather than running every time out of habit.

Why it stays manual

This project's own grounding research argues automation can't substitute for a person committing to what would actually change their mind before they've seen an answer that might sway them. Automating Stage 0 away was considered and explicitly rejected, twice.

What it achieves

Every downstream prompt template — the Stage 1 draft instructions, the grounding pass, the Stage 3.75 critique lenses, the final premortem — reads its domain content from this file alone. Nothing is hardcoded, which is what lets the same pipeline run a fundraising decision one week and an infrastructure decision the next without a rewrite.

Why it runs first

Grounding claims against evidence before anyone drafts means the council starts from checked facts instead of independently discovering — or independently hallucinating — the same document. Fetches run concurrently with a bounded semaphore and real per-call cost is summed and carried forward, closing a gap this session's own audit found: Stage 0.5 spend used to be invisible to the cost ceiling entirely.

What it achieves

A verified_facts list every later stage can point to instead of re-deriving. Claim text reaching this stage is wrapped in fixed delimiters before it ever enters a prompt, so a hostile document can't forge instructions by pretending to be part of the fact list.

How it judges evidence quality

The evidence-fetch instruction carries eight epistemic clauses, added and adversarially panel-reviewed across two later sessions — not just "find a source," but rules for weighing what's found: prefer a specific, dated, independently verifiable finding over a vague one, but score an unverified specific-sounding claim as lower trust than a hedged one, not higher; weight a finding that aggregates many independent sources (a systematic review, a meta-analysis) above a single anecdote; treat a verified action as at least as weighty as a stated forecast; credit convergence across independent spheres of activity; judge a source by whether it would be unlikely if the claim were false (diagnosticity), not just whether it sounds supportive; weight a costly or against-interest disclosure above an easy, self-serving one; refuse to treat a real proxy number as proof of a different, unconfirmed outcome unless the source itself states that link; and credit multiple sources only when they were genuinely produced by different methods, never reprints of one report. Every clause carries its own anti-fabrication guardrail defaulting to unverifiable — a self-reported citation with no real, resolvable URL behind it (checked by an actual HTTP request) never earns a verdict. Two individually-plausible techniques — weighing a source's historical base rate, and treating an unexplained silence as itself evidence — were deliberately not added: both reopen real fabrication risk for a signal that can barely move a verdict under this stage's one-search-per-claim design.

Why no persona

Assigning roles like "VC partner" or "technical advisor" was the worst-performing multi-agent-debate method across nearly all datasets in the research this pipeline is built on — role identity doesn't create real separation, it's linguistic dressing inside one chat, and it breaks the assumption behind the Consensus Strength Score computed two stages later: consensus only means something if every model answered the same question independently.

What it achieves

Each model is asked, identically, to weigh counterfactuals and potential weaknesses in its own reasoning while staying concise, and to tag every substantive claim with exactly one of three fixed markers: [grounded: document] for the input documents, [grounded: verified] for Stage 0.5's verified facts, or [unverified] for background knowledge with no checkable source. Unverified claims may still be mentioned, but never treated as citable downstream — a self-reported citation with no check behind it is closer to theater than grounding.

Strict, and machine-checked

An earlier version of this instruction leaked internal staging language into the prompt and left the tag format free-form; in a real dry run, all four peer reviewers penalized one model's answer for surfacing that scaffolding, not for its substance. The fix targeted presentation only — the grounding requirement itself got stricter, not weaker. Every Stage 1 response is now scanned for at least one of the three exact tags; a model that comes back with none is named in a dedicated compliance note threaded straight into Stage 3's chairman prompt, so a missing tag is actively questioned by the synthesizer rather than silently passed through.

Dialectic, not eristic

Every seat also reads a shared line making the frame explicit: the goal is a shared, best-supported answer, not winning an argument against the other three models drafting alongside it. Ancient rhetoric drew this exact line — eristic argument optimizes for victory, dialectic argument optimizes for arriving at the best answer together — and it's the same distinction the peer-review restructuring at Stage 2.75 leans on.

What it achieves

A verbose, hedge-heavy answer and a terse, confident one shouldn't win a peer-review vote on prose style alone. This step is explicitly instructed to never add or remove substantive content, opinions, or caveats — confirmed by reading the normalizer's own source rather than assuming its docstring — so it changes surface tone only, leaving the actual judgment differences for Stage 2 to score.

Peer review & ranking

Live
Runs on
All four seats, cross-reviewing
Target effort
None / off — ranking existing text doesn't need reasoning depth

Stage 2.5's Consensus Strength Score and outlier flags

Why self-vote exclusion

A model that could vote on its own draft could inflate its own standing in the Borda ranking. Exclusion is unconditional, not model-specific.

What it achieves

Five-dimension rubric scoring (accuracy, relevance, completeness, conciseness, clarity) plus free-text critique. Because each Stage 1 reference block rides inside the draft text itself, it's naturally visible here too — passive cross-checking at zero extra model calls, deliberately stopping short of a forced verification pass. The evidence for that heavier step comes from external-retrieval systems, not "one model eyeballing another's citation list," and unstructured peer-anchored verification risks destabilizing consensus rather than improving it.

What it achieves

Computes the Consensus Strength Score from Stage 2's rankings, and separately flags any model as an outlier — three seats tightly agreeing while one genuinely dissents, a pattern the aggregate score alone can miss. Both numbers gate everything downstream: CSS below threshold or any outlier flag is what actually decides whether the council revises instead of moving straight to synthesis.

Why gated, not automatic

Running a second debate round unconditionally is exactly the pattern this project's own cited literature found unreliable — models revising when they didn't need to tends to make answers worse, not better. Gating on measured disagreement keeps revision reserved for when it's actually warranted.

What it achieves

Each participating seat rewrites its answer with the peer critique in hand, citing back to specific fact IDs so a revision can be checked against what it claims motivated it. Runs sequentially today rather than in parallel — a known, still-open cost on the one path most likely to already be under time pressure, since it only ever fires when consensus was weak to begin with.

Rapoport's Rules, and a real fix underneath them

Before a seat may accept or reject the critique, it must first restate the critique fairly enough that a reviewer would recognize it as its own point, and note anything it agrees with — the four-step discipline philosopher Daniel Dennett credits to game theorist Anatol Rapoport for arguing productively. Building this surfaced a real, previously invisible gap: the model doing this restating had only ever seen numeric peer scores, never the reviewers' actual written justifications, even though the underlying review call collects them. That free-text critique now reaches this stage for the first time. A seat that isn't revising must also say what specific finding would change its mind, rather than only restating its disagreement — reframing the question from "why are you against this" to "what would it take."

Why one seat, and why this one

Chairman duty was assigned to the seat with the strongest track record on nuanced judgment calls with tradeoffs, not just factual correctness — matching what the job actually is. Structurally, no other seat can ever be routed into this role: the synthesis call path resolves exclusively through the pinned chairman field, confirmed by reading the routing code directly rather than trusting the config alone.

What it achieves

Stage 3's own query is now threaded with Stage 0.5's verified facts directly, through a dedicated, independently-controllable string — richer grounding for the synthesis call without building a second, riskier "centralized reference list" merged from what four models self-reported.

Why not the chairman

Having Opus critique its own synthesis would be the literal self-refine pattern the cited literature found reliably worse than doing nothing — the sharpest, most agreed-on finding to come out of designing this stage. GPT-5.5 was chosen specifically because it never wrote the thing it's attacking.

What it achieves

Only two of eight originally-considered stress-testing techniques survived evidence review — devil's-advocate critique and counterfactual/what-if framing, folded into one call. Red-blue teaming, Socratic questioning, lateral thinking, and brainstorming were each checked against the actual 2026 multi-agent-debate literature and dropped for lack of applicable evidence, not on a hunch. The output is a labeled critique memo, persisted to critique_memo.md in the run folder, for the human premortem to read alongside the synthesis — it never auto-triggers a re-synthesis, which would reopen the same revision failure mode Stage 2.75 is careful to avoid. A failed critique call never takes the run down; it's logged non-fatally and the rest of the pipeline completes.

Why one unified graph, not five

The user's own framing for this stage — concept graph, knowledge graph, reasoning chain, mind map, reference-grounding graph — already half-conceded the overlap between them. A three-judge design panel converged on building one typed graph instead of five redundant ones.

What it achieves

Reference nodes and their cites edges are built deterministically in plain Python from the verified-facts list — zero LLM involvement, zero hallucination surface for roughly half the schema. Concept and claim nodes come from a single call over the Stage 3 synthesis only, and every claim node or relationship edge must carry a verbatim source-text span, checked by a plain substring match. Anything that fails validation is dropped and counted, following the same never-flag-and-keep rule as Stage 4. A separate design decision this session rejected replacing prose debate with structured graph reasoning outright — JSON-mode outputs measurably homogenize model answers, which would quietly inflate the Consensus Strength Score and disable the Stage 2.75 gate exactly when it's needed most. This stage exists purely as an additive, after-the-fact artifact, written to the run folder alongside the other transcripts.

Why it stays manual

Same argument as Stage 0, mirrored at the other end of the pipeline: no amount of automated critique substitutes for a human weighing failure modes against the criteria they committed to before any of this ran. The council's job ends at producing the best-checked answer it can; the decision itself is never delegated to it.

Synthesis

What actually makes this "unbiased"

No single mechanism does this. It's the combination — and each one below was chosen because a specific, named failure mode would otherwise slip through.

01

No personas, ever

Every seat answers as itself. Role-play was measured as the worst-performing debate method in the cited research, and it would quietly break what "consensus" even means at Stage 2.5.

02

Self-vote exclusion

No model ever scores its own Stage 1 draft in Stage 2's peer review. Unconditional, not a threshold.

03

Gated, not habitual, revision

Stage 2.75 only fires below a measured consensus threshold. Revising by default was the pattern the literature found makes answers worse.

04

Outlier detection alongside consensus

A single dissenting seat against three tightly-agreeing ones can hide inside a healthy-looking aggregate score. Stage 2.5 flags that case explicitly.

05

The critic is never the author

Stage 3.75's design keeps the chairman out of its own critique loop — self-critique on one's own output is a documented failure mode, not a hypothetical one.

06

Grounding before drafting

Stage 0.5 checks document claims against evidence before any model writes a word, so the council starts from the same checked facts instead of independently re-deriving — or re-hallucinating — them.

07

Cite-or-don't-write, extended into the pipeline itself

Stage 1 restricts citable claims to document text and verified facts; unverified background knowledge is labeled as such and never treated as grounding downstream.

08

Untrusted text stays fenced

Document and claim text is wrapped in fixed delimiters before it reaches any prompt, so a hostile document can't forge instructions by imitating the fact list around it.

09

A dropped seat never goes silent

If a primary model is genuinely unreachable, ranked backups are tried in order before the council proceeds degraded — loudly, with an explicit shortfall warning, never a quiet drop.

10

Seat changes are evidence-gated

GLM-5.2's standing, and any future seat change, is tracked against 20+ recorded scorecard sessions — a graduation bar, not a discretionary swap.

11

Evidence is judged, not just found

A source that would look identical whether the claim were true or false earns little credit even if it's real and well-sourced (diagnosticity). A verified action outweighs a stated forecast. A costly, against-interest disclosure outweighs an easy, self-serving one. Finding a source is necessary; it was never sufficient.

12

Restate before you rebut

Before declining to revise, a seat must restate the critique fairly enough that the reviewer who wrote it would recognize it as their own point. Borrowed from the same discipline philosopher Daniel Dennett credits to game theorist Anatol Rapoport — it only works because real peer critique text now actually reaches this stage, not just numeric scores.

Considered and rejected this session

A fifth standing seat
Pushes Stage 2's review-pair count from 6 to 10 — a 67% cost jump — for a literature-estimated gain of roughly one accuracy point at this point on the curve. Rejected unanimously by a four-judge panel.
Structured graph/JSON reasoning in place of prose
JSON-mode outputs measurably homogenize model answers, which would inflate the Consensus Strength Score without genuine independent convergence — a direct threat to the pipeline's primary quality gate, not a token-cost tradeoff.
Forced peer-to-peer citation cross-verification
The literature's positive results come from heavier apparatus — external retrieval, dedicated verifier pipelines — not one model eyeballing another's citation list. Unstructured peer-anchored checking risks destabilizing consensus into oscillation instead of improving it.
Red-blue teaming, Socratic questioning, lateral thinking, brainstorming
Checked against the 2026 multi-agent-debate literature specifically. Red-blue teaming turned out to be a false cognate for AI-safety red-teaming; the others returned no applicable evidence in this context — absence of evidence, not disproof, so not shipped on a hunch.
Historical base-rate weighting and "absence of an expected signal"
Both real, well-evidenced techniques from forecasting and warning-intelligence tradecraft — and both declined anyway. Each only fires safely under narrow conditions this pipeline's single-search-per-claim design rarely meets, and each reopens exactly the fabrication risk the "prefer a specific finding" clause already manages, for a signal that could barely move a verdict.
Iterative revision until a consensus threshold is met
A real characteristic of successful human deliberation — but the opposite of what this pipeline's own cited literature found for LLM multi-agent debate specifically: repeated revision rounds tend to degrade answers, not improve them. Stays a single, CSS-gated pass. Human-deliberation best practice, applied uncritically, would have been the wrong call here.
Compute allocation

Reasoning effort, stage by stage

OpenRouter's unified reasoning contract lets a caller request an effort level per call — none, minimal, low, medium, high, xhigh, max — instead of paying frontier-depth reasoning for a task that doesn't need it.

Live, for the stages this repo controls directly Stage 2.75, Stage 3.75, and Stage 4 now send a real top-level reasoning_effort field on every call — confirmed working in a real dry run, not just unit-tested. Grounding found the nested reasoning: {effort, max_tokens} object has real per-provider mutual-exclusivity quirks (Anthropic accepts max_tokens only, not effort); this project sidesteps that entirely by using OpenRouter's simpler top-level field instead, confirmed supported by all 4 core models via a live catalog fetch. Stage 1, Stage 2, and Stage 3 remain unsent — their call paths go through the installed package's own orchestration functions, which don't accept a reasoning parameter at all today. That's an upstream gap, not something this repo can wire around without a bigger, separately-scoped call-path swap.

Fixed this session

  • Crash guards added for the two shapes that used to take the pipeline down outright — every model failing Stage 1, and exactly one model surviving it.
  • Wall-clock and cost budgets redesigned as an absolute deadline threaded through retries and backup substitution, so a sustained outage can no longer both trigger the resilience layer and blow through the ceiling at the same time.
  • Real spend is no longer invisible on a mid-call timeout, and Stage 0.5's evidence-fetch cost is now tracked and summed into the total instead of silently dropped.
  • Durable persistence added — Stage 1 through Stage 4 output now actually gets written to the run folder. It used to only ever reach stdout.
  • Mutation-testing coverage restored across all 13 implemented scripts, after 5 had silently stopped generating any mutants at all.
  • Prompt-injection delimiting completed everywhere untrusted document or claim text reaches a model prompt, closing the one case that had been left unguarded.
  • Two dead OpenRouter slugs fixed (GLM, then Kimi) after each was independently caught by direct catalog verification rather than trusted from memory.
  • Stage 0.5 and Stage 2.75's HTTP calls preempt cleanly. Both were synchronous urllib calls that blocked the event loop against the wall-clock deadline; wrapping them in asyncio.to_thread lets the outer asyncio.wait_for actually fire on schedule instead of waiting for the call to finish on its own. Verified by a direct regression test, not just by reading the diff.

Still open

  • The safety gate is surfaced, not enforced. A regex scan runs against Stage 1 drafts and now produces a debug-log warning for any flagged model — but still no score cap and no abort. A human reading the run log will see it; the pipeline itself doesn't act on it.
  • Stage 2.75 revision still queries models sequentially, multiplying wall-clock cost by seat count on the path most likely to already be under pressure.
  • Reasoning-effort parameters are designed (see above) but not implemented for any stage.
  • Three lower-severity items are explicitly deferred, not silently dropped: a nine-element result tuple that should be a named dataclass, opaque numeric IDs in the Stage 4 dropped-facts warning instead of readable claim text, and one remaining debug-log line still using the pre-rename "Stage 1–3.5" label.
  • Stage 0.5's evidence-weighting instruction has grown to eight epistemic clauses and has not yet been dry-run against a real model on a real decision. Every clause is unit-tested for exact wording and anti-fabrication guardrails, but whether a real retrieval model correctly applies eight distinct weighting principles in one pass — rather than a subset of them, or none — is untested behavior, not just untested code. This pipeline's own Real-money gate already requires a dry run before real use; that requirement now carries more weight than it did before this stage's instruction tripled in size.
  • Whether Gemini 3.6 Flash's peer-review vote should be weighted below the three frontier seats it's nominally an equal peer to remains an open, undecided question — on file since before this session, not resolved by anything built here.
